# Development preview: gated ranked-ballot foundation

Runtime commit: `b3d0a09`. Preview Worker version: `8e6753a2-3862-477e-b05e-f85b1dbda16e`, verified serving 100% of preview traffic on 2026-10-13.

The Kindle PoC defines three authored simulated candidates, a frozen candidate slate, one 72-real-hour window, complete ranked ballots, one participation receipt per verified human, and an immutable closed count. Aggregate results remain hidden until close. The instant-runoff implementation transfers preferences after elimination and uses the published candidate order for equal-lowest ties. Human ballots have four count units each; a fixed Simulated Public bloc has one unit per human ballot, capping its share at 20%. No humans means zero bloc weight and no winner. Counts use grouped rankings, rather than expanding all ballots in memory. The PoC records counts; it does not replace the incumbent or implement the full election cycle.

Live voting is unavailable. The trusted Tier-1 provider remains absent, and a separate privacy-readiness gate is hardcoded closed. Client claims, user metadata and environment flags cannot unlock either gate. While privacy is unreviewed, the POST refuses before authentication or ranking parsing. Unverified/unreviewed visits do not start an election clock. The native Civic ballot form uses the Kindle document theme, shows simulated-candidate badges and explicit disabled reasons, and preserves an identical receipt across interrupted retries. Inbox ballot alerts require an actual open window, reviewed privacy and an uncast ballot in the citizen's own nation.

Privacy limits: stored ranking rows have independent random UUIDs and contain no citizen identifier, receipt ID, per-ballot timestamp or rowid. Participation receipts contain no ranking or ballot ID. The application adds no ballot-content logging. **This is structural table separation, not verified end-to-end unlinkability.** An authenticated submission and its database transaction can permit operator or platform-log correlation; small-population aggregate results can also permit inference. No cryptographic blind-submission protocol or platform logging audit was completed. Do not flip the readiness gate merely because Tier-1 verification becomes available. Resolve and review the protocol, logging and inference threat model before live voting.

Validation: 236 Node tests, 98 SQL tests, lint, TypeScript and build passed. Fixtures cover exact window boundaries, reopening without clock reset, deduplication and receipt collisions, ranking immutability, result secrecy before close, separate human/bloc tallies, zero-vote results, closed-state persistence on a reversed clock, citizenship locking, stored-table separation, and request-claim rejection at the production privacy gate. UI fixtures cover disabled direct handlers, invalid rankings, immutable retry, foreign namespace rejection and closed-only result rendering. Desktop/mobile screenshots verify the actual Kindle ballot component, contained controls and explicit waiting reasons, with no horizontal overflow. Positive voting tests substitute privacy readiness only in temporary compiled fixture modules; they do not verify operational anonymity or configure live access.

Live checks: the anonymous election GET returns HTTP 401 with `private, no-store`; normal world loading succeeds and initializes the additive schema. Read-only D1 checks confirmed zero election windows, zero participation receipts, and zero anonymous ballots. The anonymous table has `WITHOUT ROWID` and only its random ID, election ID, ranking JSON and fixed eligibility policy columns. All inspected queries reported zero rows written.
